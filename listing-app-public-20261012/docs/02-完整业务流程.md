## 每一步共同执行边界

可见执行器大体遵循：检查当前 task/step 与上游 QA；锁定输入版本；取得 SKU、步骤、输入版本范围内的 lease；读取经 resolver 验证的上游 artifact；运行本地规则、外部接口或 AI；校验 Schema、事实和证据 refs；持久化正式 artifact/version；Stage QA PASS 后才推进 last_success/current_step；终态释放或明确关闭 lease。

某个运行部署是否对每一步完全使用相同事务包装，必须由该版本代码和 runtime event 核验，不能由设计文档推断。

## 两条竞品工作线

Listing SOP08–09 属于主线。COMPETITOR_RESEARCH_STEPS 是独立调研工作线，拥有独立 task、pool、事件和版本，不自动推进 Listing task。不能把调研中的采购风险/采购动作混入 Listing SOP09。

## 外部依赖关口

- SOP03/SOP04 可能依赖 BOL 搜索词或 Boloo 页面操作。
- SOP06 先查正式 keyword library，只有当日 identity 完全匹配时复用。
- SOP08 existing evaluation 优先读取本地证据；需要补充时才进入远端补充阶段。
- SOP09 读取正式竞品池和已持久化 BOL/Amazon Evidence Bundle；不应隐式重新发现商品。
- SOP10–17 依赖正式上游版本；AI 调用不会跳过后续 QA。

## 正式输出与发布界限

SOP17 表示 Listing 内容最终质量审查，不等于 BOL 上传、ERP 提交或公开发布。核心代码把 Excel 写入/readback、await-upload 和 archive 列为后续 release gate；这些是不同权限和副作用。

## “卡住”时的排查顺序

查看 current_step、last_success、resume_point、dependency key、QA、OPEN errors、active leases、recent events 和 artifact。先区分上游未 PASS、外部依赖无新鲜 evidence、artifact/ref QA 失败、state 与 lease 不一致、worker异常或 runtime停机。不能只看浏览器页面、HTTP 200、task的 RUNNING 字样或旧 runtime lock。
