# 07｜AI 模型调度系统

## 注册与路由

ai_provider_adapters.mjs建立Provider adapter；ai_router.mjs负责注册、读取路由配置、评估readiness并分发请求；ai_worker_pool.mjs提供worker pool抽象。真实Provider配置与凭据不随公开快照发布。

## 请求身份和provenance

正式AI请求应记录provider、configured/requested model、effective request model、returned model、adapter version、request trace ID和可用usage。完整identity还包含step、输入版本/SHA、prompt contract/hash、schema/output contract。普通日志不应记录prompt或模型正文。

## Readiness != generation

- Control-plane readiness只说明健康/配置探针可以运行，不证明长业务生成可用。
- Generation readiness应使用合成、非机密输入经过真实生成、JSON/schema和延迟检查。
- Recovery route只对匹配的provider、model、input、prompt、adapter identity有效，并要求probe新于failure barrier且在TTL内。

不能用旧probe全局重置另一个model或任务的失败屏障。

## Partial checkpoint

Provider成功可保存AI_PROVIDER_PARTIAL_RESULT，以避免恢复时重调已成功provider。partial必须同identity复用；它不是正式SOP artifact、Stage QA PASS，也不能单独推进下游。

状态至少包括NOT_STARTED、RUNNING、SUCCESS、CACHED_SUCCESS、TIMEOUT、FAILED、STALE。

## JSON / Responses

DeepSeek Listing代码含Responses protocol、json_schema和reasoning effort none路径。Adapter区分completed、incomplete和failed；只有completed且JSON/Schema PASS才算provider SUCCESS。Qwen协议随运行配置和步骤合同确定，不应仅凭模型名猜测。

## Circuit与重试

生成失败分类包含timeout、empty content、truncation、invalid JSON、schema invalid和transport failure。Probe是受控recovery evidence，不是无限重试许可。Adapter transport retry、Provider generation attempt、SOP step retry必须分开统计。

## Acceptance degraded mode

Acceptance控制通过精确作用域校验。若降级AI获授权，必须记录degraded标志、失败provider、实际provider和failure evidence；不能把单provider结果伪装成双provider生产通过。GPT/OpenAI未配置或未授权时不可接入。

## 失败处理

- 区分adapter未注册、配置缺失、control-plane不可用和generation timeout。
- HTTP 200不掩盖空内容或Schema失败。
- returned_model未由响应提供时标NOT_REPORTED。
- Provider failure应进入依赖等待并保留精确recovery identity，不能直接伪造成SKU业务错误。
