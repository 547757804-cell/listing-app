# 10｜状态机及 QA 系统

## 关键游标

- current_step：当前要执行的步骤。
- last_success_step：最近Stage QA PASS的正式步骤。
- resume_point：恢复后继续的位置，可能与current_step不同。
- waiting_dependency_key：精确等待依赖。
- stage_qa_status：步骤质量门禁。
- OPEN_ERROR_COUNT：未解决business errors数。
- active lease：运行中执行持有者。

核心task快照在SQLite产品表中；事件保留状态变化历史。

## HOLD 与effective policy

runtime_mode.mjs集中计算effective policy，包括acceptance hold、business dispatch、dependency resume、background probe和task mutation。HOLD=true应关闭业务派发和自动恢复；health输出须使用当前effective policy，不能混合配置原值和缓存策略。

某些本地/人工操作在HOLD下有窄allowlist；仍须检查action、SKU、dataRoot、revision和lease。

## PASS门槛

1. 输出满足Schema。
2. evidence refs resolve。
3. 产品事实及来源边界QA通过。
4. artifact持久化且版本可读。
5. Stage QA PASS记录到task。
6. last_success和next step更新。

DONE不等于PASS；上游QA失败或未运行时，下游不得生成PASS。

## Lease状态机

~~~mermaid
stateDiagram-v2
  [*] --> ACQUIRED
  ACQUIRED --> RUNNING: worker确认
  RUNNING --> PASS: artifact与QA成功
  RUNNING --> FAILED: 内部异常
  RUNNING --> WAITING_DEPENDENCY: 可恢复依赖失败
  RUNNING --> WAITING_CONFIRMATION: 真正人工事项
  RUNNING --> WAITING_DECISION: 规则要求选择
  RUNNING --> CANCELLED: 显式取消
  FAILED --> RECOVERING: stale检查与recovery授权
  RECOVERING --> RUNNING
~~~

lease作用域是SKU、step、input version；含owner与heartbeat。duplicate suppression只写审计，不污染SKU业务状态。终态和等待转移需要释放/关闭lease。

## QA层次

- Stage QA：单步输入/输出合同与evidence。
- Final QA：跨步骤Facts、版本、stale、error、语义一致性。
- Excel FILE_QA/readback：工作簿结构、填充和回读。
- 视觉核验：实际渲染可读性和溢出。

未真实运行必须标NOT_RUN/UNVERIFIED。

## 本地状态校正

RECONCILE_LOCAL_TASK_STATE类型动作用于revision CAS保护的状态修复；保留历史事件，写新audit与本地决策artifact；禁止dispatch executor、外部请求或创建lease。
