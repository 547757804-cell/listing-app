# 08｜数据库和数据结构

## SQLite表

bol_core.mjs使用Node内置node:sqlite DatabaseSync。公开源快照明确创建/使用：

| 表 | 用途 |
|---|---|
| products | 当前task快照：revision、state、step、QA、error和JSON payload |
| product_versions | SKU task历史快照 |
| task_events | task事件流，按SKU/sequence索引 |
| uploaded_finals | final/archive元信息 |
| competitor_research_tasks | 独立竞品调研task |
| competitor_research_versions | 独立调研版本 |
| competitor_research_events | 独立调研事件 |
| listing_execution_leases | SKU-step-input version execution lease |

这不是对内部dataRoot所有数据库/表的穷举。

## Task payload与revision

字段包括SKU、revision、status、current_step、resume_point、last_success_step、stage QA、error、retry count及业务payload。payload可携带Listing registry、artifact refs、waiting items和阶段checkpoint。

revision用于并发控制；状态改动应使用expected revision CAS。不能回写旧revision迎合fixture。

## Event stream

事件记录时间、SKU、类型、step、pool和details。审计式恢复应保留旧失败事件，用新事件描述状态校正，不删除历史。

## Version与文件系统

正式artifact通常是独立JSON/manifest并由task引用。version与SHA应交叉验证。数据库行存在不代表文件bytes可读；artifact ref存在不代表pointer真实存在。

## Lease

listing_execution_leases记录lease/execution ID、SKU、step、input version、worker、started/heartbeat、state、result state、ended time、recovery count等。active lease应抑制重复dispatch；stale lease需先验证worker/heartbeat再恢复。

## 安全边界

真实数据库和evidence库未随公开仓库发布，避免SKU、供应商、评论、任务事件及凭据metadata泄露。公开测试应使用合成数据；不能把业务数据库复制到公开包。

## 备份恢复

infra/backup_restore.ps1和infra/sqlite_backup_verify.mjs提供备份与校验入口。production恢复能力没有由公开源码快照证明。
