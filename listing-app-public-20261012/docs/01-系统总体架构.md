# 01｜系统总体架构

## 阅读边界

本文描述公开发布快照中可见的实现，不表示内部所有 Provider、数据根和运行服务均可由仓库独立启动。快照排除了真实配置、数据库、浏览器会话、运行数据与编译产物。无法从源代码确认的部署状态标为“未验证”。

## 架构分层

~~~mermaid
flowchart LR
  UI[工作台与页面采集壳] --> HTTP[本地 HTTP Server]
  HTTP --> CORE[业务核心与任务状态]
  CORE --> DB[(SQLite)]
  CORE --> SOP[Listing 执行器与 Stage QA]
  SOP --> EVIDENCE[Evidence Resolver / Version Lock]
  SOP --> ROUTER[AI Router / Worker Pool]
  ROUTER --> Q[Qwen Adapter]
  ROUTER --> D[DeepSeek Adapter]
  CORE --> BOL[BOL Retailer Adapter]
  CORE --> LIB[Boloo Keyword Volume Library]
  UI --> BRIDGE[WebView2 Bridge]
  BRIDGE --> PANE[Boloo / BOL / Amazon 页面]
~~~

### 1. 工作台与服务入口

- app/bol_server.mjs 提供本地 HTTP API、健康信息及任务动作入口。
- app/bol_core.mjs 聚合数据库读写、任务状态机、依赖恢复、SOP 编排和运行时保护。它是大型核心模块，也是耦合和回归风险的主要集中点。
- ui_shell/ 包含桌面壳、工作台 UI、页面探针 Bridge 的源码。公开副本不含已编译程序与用户浏览器 Profile。

### 2. 业务与数据层

- SQLite 持久化任务快照、版本、事件、竞品调研任务和执行 lease。
- 产品任务 payload 中包含当前步骤、最近成功点、QA、依赖等待和产物引用。
- 不可变产物与 evidence 文件保存在运行 dataRoot；数据库引用需经 resolver 验证，单独存在的引用文本不构成证据。

### 3. 外部能力层

- BOL Retailer Adapter 负责 API 调用、readiness 和结构化错误诊断。
- Boloo 有 Web/MCP 接入与精确搜索量库两种能力。搜索量事实可按精确词共享，商品相关性与 TOP20 决策仍按 SKU 隔离。
- AI Router/Worker Pool 管理 Qwen、DeepSeek 主流程与可选 provider。业务响应需经结构化解析、Schema 与 SOP Stage QA。
- BOL/Amazon Page Probe 使用桌面壳与 Bridge 读取页面并持久化字段状态和 DOM evidence refs；页面打开或 Bridge 心跳本身不等于采集成功。

## 隔离原则

1. 业务 SKU、Evidence、partial cache、lease 与 task 事件按 dataRoot/SKU 作用域隔离。
2. Acceptance Runtime 与 Production Runtime 应以不同端口、标记和 dataRoot 分离；公开快照不能证明当前生产部署状态。
3. 页面事实、API 事实和 SOP 结论是独立 evidence layer，不得互相覆盖。
4. Provider 返回、正式 SOP artifact、Stage QA PASS 是不同阶段；HTTP 200 不能替代业务通过。

## 已知架构风险

- bol_core.mjs 体积很大，包含多个 SOP 的编排和恢复分支；局部改动需要跨状态回归。
- 快照不含完整部署清单与安全配置，开发者不能仅凭此快照复原生产数据根。
- 部分 acceptance 控制通过精确作用域 allowlist 实现；变更时应保持窄范围并用合成 SKU 测试。
